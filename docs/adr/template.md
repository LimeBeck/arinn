## Context

What forces the decision: requirements, constraints, evidence. Link sources instead of copying them.

## Decision

The decision in active voice ("Arinn uses …"). State scope and defaults precisely enough to implement and test.

## Consequences

What becomes easier or harder. New obligations for code, tests, docs or operations.

## Alternatives considered

Options that were rejected and why. Write "None evaluated" rather than inventing alternatives.

## Verification

How to confirm the decision holds: tests, acceptance criteria (AC-xx), gates, evidence files. Accepting an ADR never means the verification has passed.
